# Evidence

Hackathon judges require exported IBM Bob task sessions and consumption summaries inside the
submission repository. This note explains what lives in `bob_sessions/`.

## Required contents (per Bob task used to build CDR)

1. Screenshot of the task session consumption summary (Bobcoins per task) as `*.png`.
2. Exported task history markdown from Bob IDE (History → task → Export task history).

## Naming convention

```text
phase-1-chaos-runner.md / .png
phase-2-classifier.md / .png
phase-2-dashboard.md / .png
phase-3-watsonx-diagnosis.md / .png
phase-4-verification.md / .png
bobshell-<task-name>-<timestamp>.json     # headless Bob Shell sessions (auto-generated)
```

## Headless session log

| Task | Mode | Bobcoins | Evidence file |
| --- | --- | --- | --- |
| queue-unit-tests | agent | 0.94 | `bobshell-queue-unit-tests-*.json` |
| concurrency-bisector | agent | 0.28 | `bobshell-concurrency-bisector-*.json` |

The JSON files contain the full `bob run` result object: `task_id`, `duration_ms`,
`session_costs` (Bobcoins), `tool_calls` and the final message. They are generated by
`scripts/bob-task.ps1` (see [[IBM Bob Integration]]).

## Rules

- **Never include credentials or API keys** in exports or screenshots. IBM scans submission
  repositories and deactivates accounts that leak Bob or IBM Cloud credentials.
- Keep sessions scoped to this project workspace.
- Export progressively during the build — do not wait until submission time.
- Budget awareness: the trial has 50 Bobcoins; each headless/runtime session records its cost.

## Runtime evidence (product, not hackathon bookkeeping)

Every dashboard run also stores Bob evidence in Supabase: `diagnoses.bob_task_id`,
`diagnoses.bobcoins`, `patches.bob_task_id`, `patches.bobcoins`, plus the real diff and changed
files. That is the strongest "application of technology" proof: Bob's work is traceable from
the UI per run.
